# ESP32-S3 + BMI160 + 双舵机开发说明

本文档对应本目录当前的固件实现，源文件为 `main/main.c`。系统功能如下：

- ESP32-S3 使用 SPI 读取 BMI160 六轴 IMU。
- ESP32-S3 优先作为 Wi-Fi STA 加入路由器；未发现或无法连接目标网络时会开启配网热点。
- ESP32-S3 内部计算 Roll、Pitch、Yaw；PC 浏览器只负责 Three.js 的 3D 渲染。
- GPIO8 和 GPIO9 分别输出两路 50 Hz PWM，驱动两个 180 度位置舵机。

## 1. 硬件与供电

### 1.1 Wi-Fi 自动配网

首次启动时，固件会扫描默认网络 `your-wifi-ssid`。如网络不存在，或连续连接失败，会开启热点：

| 项目 | 值 |
| --- | --- |
| 热点名称 | `BMI160-Setup` |
| 热点密码 | `12345678` |
| 配网页面 | `http://192.168.4.1/` |

手机或电脑连接该热点后，打开配网页面并输入目标 Wi-Fi 的 SSID 和密码。配置保存到 NVS，设备随后关闭热点、连接新网络；重启后会优先使用已保存的配置。

### 1.2 BMI160 接线：SPI 四线模式

当前 BMI160 不是 I2C 模式，而是 SPI 模式。模块上标为 `SCL`、`SDA` 的引脚在 SPI 模式下分别是时钟和 MOSI。

| BMI160 模块引脚 | ESP32-S3 引脚 | SPI 信号 | 说明 |
| --- | --- | --- | --- |
| `3V3` | `3V3` | 电源 | 当前接法，使用 3.3V |
| `GND` | `GND` | 地 | 必须共地 |
| `SCL/SCX` | GPIO4 | SCLK | SPI 时钟 |
| `SDA/SDX` | GPIO5 | MOSI | ESP32 -> BMI160 数据 |
| `SAO/SDO` | GPIO7 | MISO | BMI160 -> ESP32 数据 |
| `CS` | GPIO6 | CS | 片选，低电平有效 |

`VIN`、`INT1`、`INT2`、`OCS` 在当前工程中不使用，应保持不接。不要同时给 `VIN` 和 `3V3` 供电。

当前 SPI 配置如下：

```c
#define SPI_HOST SPI2_HOST
#define SPI_SCLK_GPIO GPIO_NUM_4
#define SPI_MOSI_GPIO GPIO_NUM_5
#define SPI_MISO_GPIO GPIO_NUM_7
#define SPI_CS_GPIO GPIO_NUM_6
#define SPI_CLOCK_HZ 1000000
```

固件启动时会读取 BMI160 `CHIP_ID`；正常日志应包含：

```text
BMI160 SPI CHIP_ID=0xD1
BMI160 output data rate: 200 Hz
```

如果 `CHIP_ID` 不是 `0xD1`，优先检查 CS、MISO、MOSI、SCLK 的实际连通性和共地，而不是修改姿态算法。

### 1.2 两个 180 度舵机接线

| 舵机 | 信号线 | ESP32-S3 | 电源正 | 电源负 |
| --- | --- | --- | --- | --- |
| 舵机 1 | 通常为橙色/黄色 | GPIO8 | 外部 5V | 外部电源 GND |
| 舵机 2 | 通常为橙色/黄色 | GPIO9 | 外部 5V | 外部电源 GND |

必须把 **外部 5V 电源 GND 和 ESP32 GND 相连**，否则 PWM 信号没有共同参考电平，舵机可能抖动、失控或完全不响应。

不要用 ESP32 的 `3V3` 引脚给舵机供电，也不建议直接用 ESP32 USB 口的 5V 给两个舵机供电。舵机启动、堵转或快速换向时电流会明显增大，供电压降可能让 ESP32 重启或 Wi-Fi 掉线。建议使用足够电流能力的独立稳压 5V 电源，并与 ESP32 共地。

当前 PWM 参数：

```c
#define SERVO_GPIO GPIO_NUM_8
#define SERVO2_GPIO GPIO_NUM_9
#define SERVO_FREQUENCY_HZ 50
#define SERVO_MIN_US 500
#define SERVO_MAX_US 2500
#define SERVO_PERIOD_US 20000
```

舵机 1 使用 `LEDC_CHANNEL_0`，舵机 2 使用 `LEDC_CHANNEL_1`，共享 `LEDC_TIMER_0`。固件把命令角度限制在 `0..180`，并将其线性映射到 500 至 2500 us 的高电平脉宽：

```c
pulse_us = 500 + (2500 - 500) * angle / 180;
duty = pulse_us * ((1U << LEDC_TIMER_14_BIT) - 1) / 20000;
```

不同型号的 180 度舵机机械极限不同。如果接近 0 或 180 度时出现持续嗡鸣、明显发热或顶死，应把 `SERVO_MIN_US`、`SERVO_MAX_US` 缩小，例如改为 600 和 2400，再重新烧录。

## 2. 网络与运行方式

固件作为 STA 加入如下路由器：

```c
#define EEI_WIFI_SSID "your-wifi-ssid"
#define EEI_WIFI_PASSWORD "your-wifi-password"
```

IP 由路由器 DHCP 分配。当前测试时的地址是 `http://192.168.1.50/`，但该地址不是固定值。每次启动都应以串口日志为准：

```text
Open http://192.168.1.xxx/ on the PC
```

PC 与 ESP32 必须连接到同一个路由器局域网。网页的 3D 模型不在 ESP32 上渲染：ESP32 发送姿态数据和网页文本，PC 浏览器下载 Three.js 并通过 WebGL 渲染模型。网页引用了 jsDelivr 的 Three.js；首次打开页面时，PC 需要能够访问该 CDN，或二次开发时把 Three.js 保存到本地并由 ESP32 提供。

## 3. 姿态计算

### 3.1 采样与量程

| 项目 | 当前值 |
| --- | --- |
| BMI160 加速度计量程 | +/-2g |
| BMI160 陀螺仪量程 | +/-250 deg/s |
| BMI160 输出速率 | 200 Hz |
| 固件传感器任务周期 | 5 ms，约 200 Hz |
| 姿态 WebSocket 推送频率 | 20 Hz |

底层采样参数在代码中为：

```c
#define SENSOR_PERIOD_MS 5
#define WS_PUSH_DIVIDER 10
#define BMI160_ODR_200HZ 0x29
#define BMI160_ACC_RANGE_2G 0x03
#define BMI160_GYR_RANGE_250DPS 0x03
```

### 3.2 当前默认模式

默认模式是 `accel_yaw`，即：

- Roll：直接由加速度计计算倾角。
- Pitch：直接由加速度计计算倾角。
- Yaw：陀螺仪 Z 轴角速度按时间积分。

对应公式：

```c
roll_acc  = atan2f(-ay, -az) * 57.29578f;
pitch_acc = atan2f(ax, sqrtf(ay * ay + az * az)) * 57.29578f;
gyro_yaw += gz * dt;
```

加速度计可以借助重力给出 Roll/Pitch 的绝对倾角，但无法从重力中确定绕竖直轴的 Yaw。BMI160 模块本身没有磁力计，因此 Yaw 无法获得长期绝对参考，会随陀螺仪零偏逐渐漂移。这是传感器组合的物理限制，不是网络丢帧造成的。

网页提供的姿态模式：

| `m` 值 | 名称 | 输出方式 |
| --- | --- | --- |
| `fusion` | 融合 | Roll/Pitch 使用互补滤波，Yaw 使用陀螺仪积分 |
| `gyro` | 仅陀螺仪 | 三轴均由角速度积分 |
| `accel` | 仅加速度计 | 仅 Roll/Pitch，Yaw 固定为 0 |
| `accel_yaw` | 倾角 + Yaw | 加速度计 Roll/Pitch + 陀螺仪 Yaw，默认 |

`复位` 不会改变传感器内部物理姿态，而是把按钮点击时的 Roll/Pitch/Yaw 记录为零点。因此应先把面包板摆到期望的“标准正向”，再点击复位。

`GX/GY/GZ 反向` 会同时翻转对应的陀螺仪和加速度计坐标，并自动请求新的零点。若模块倒装或某一轴方向与 3D 模型相反，用它进行坐标系匹配。

## 4. Web API 与 WebSocket 协议

HTTP 服务配置为最多 10 个 URI handler。这一点不能随意减小，否则新增接口可能触发 `ESP_ERR_HTTPD_HANDLERS_FULL` 并重启。

### 4.1 HTTP API

| 方法 | 路径 | 用途 | 示例 |
| --- | --- | --- | --- |
| GET | `/` | 网页控制台 | `http://192.168.1.50/` |
| GET | `/imu` | 获取当前状态 JSON | `curl http://192.168.1.50/imu` |
| POST | `/reset` | 当前姿态设为零点 | `curl -X POST http://192.168.1.50/reset` |
| POST | `/mode?value=...` | 切换姿态模式 | `curl -X POST "http://192.168.1.50/mode?value=accel_yaw"` |
| POST | `/invert?axis=...&value=...` | 翻转指定轴 | `curl -X POST "http://192.168.1.50/invert?axis=gz&value=1"` |
| POST | `/servo?angle=0..180` | 设置 GPIO8 舵机 | `curl -X POST "http://192.168.1.50/servo?angle=90"` |
| POST | `/servo2?angle=0..180` | 设置 GPIO9 舵机 | `curl -X POST "http://192.168.1.50/servo2?angle=90"` |

`/servo` 和 `/servo2` 用于控制 WebSocket 未连接时的后备路径。不要在循环里无节制地高频请求它们；二次开发时应使用下面的 `/control` WebSocket，或保持“同一时刻最多一个 HTTP 请求”的队列策略。

### 4.2 `/imu` JSON 示例

```json
{
  "r": 1.74,
  "p": 4.52,
  "y": 4.68,
  "gx": 0.02,
  "gy": 0.66,
  "gz": 0.15,
  "m": "accel_yaw",
  "ix": 0,
  "iy": 0,
  "iz": 0,
  "s": 90,
  "s2": 90
}
```

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `r` / `p` / `y` | Roll / Pitch / Yaw 输出角 | deg |
| `gx` / `gy` / `gz` | 处理过轴反向后的陀螺仪角速度 | deg/s |
| `m` | 当前姿态模式 | 字符串 |
| `ix` / `iy` / `iz` | 对应轴是否反向，`0` 或 `1` | 布尔值 |
| `s` | GPIO8 舵机目标角度 | deg |
| `s2` | GPIO9 舵机目标角度 | deg |

### 4.3 姿态 WebSocket：`/ws`

连接：

```javascript
const telemetry = new WebSocket('ws://192.168.1.50/ws');
telemetry.onmessage = event => {
  const state = JSON.parse(event.data);
  console.log(state.r, state.p, state.y);
};
```

ESP32 大约每 50 ms 发送一帧，载荷格式与 `/imu` 完全相同。该连接用于遥测，当前实现只记录一个客户端 socket；多客户端同时查看时，最后建立的连接会成为接收推送的客户端。二次开发需要多客户端时，应改为遍历 HTTP server 会话，而不是只保存一个 `ws_fd`。

### 4.4 舵机控制 WebSocket：`/control`

连接：

```javascript
const control = new WebSocket('ws://192.168.1.50/control');
```

命令是纯文本：

| 控制对象 | 发送文本 | 设备返回 |
| --- | --- | --- |
| GPIO8 舵机 | `servo1:90` | `ok1:90` |
| GPIO9 舵机 | `servo2:135` | `ok2:135` |

浏览器二次开发参考：

```javascript
function setServo(channel, angle) {
  const safeAngle = Math.max(0, Math.min(180, Math.round(angle)));
  if (control.readyState === WebSocket.OPEN) {
    control.send(`servo${channel}:${safeAngle}`);
  }
}

control.onmessage = event => console.log('ESP32 confirmed:', event.data);
```

控制端应保持 30 ms 以上的发送间隔，约等于每个舵机最高 33 Hz；拖动滑杆时只保留最新目标值。这样既足以获得流畅的人机控制，也不会向 ESP32/TCP 缓冲区堆积过多已过期的角度命令。

## 5. ESP-IDF 构建与烧录

工程目录：

```text
<firmware 目录>
```

当前开发板识别为 `COM6`。在已加载 ESP-IDF 环境的 PowerShell 中执行：

```powershell
cd <firmware 目录>
idf.py build
idf.py -p COM6 flash monitor
```

如果 ESP-IDF 环境变量没有初始化，可先执行：

```powershell
$env:IDF_PYTHON_ENV_PATH='C:\esp\Espressif\python_env\idf5.5_py3.11_env'
. C:\esp\Espressif\frameworks\esp-idf-v5.5.5\export.ps1
$env:IDF_TARGET='esp32s3'
```

`sdkconfig.defaults` 中必须保留：

```text
CONFIG_HTTPD_WS_SUPPORT=y
CONFIG_HTTPD_WS_POST_HANDSHAKE_CB_SUPPORT=y
CONFIG_FREERTOS_HZ=1000
```

## 6. 二次开发入口

| 目标 | 主要修改位置 |
| --- | --- |
| 修改 Wi-Fi | `WIFI_SSID`、`WIFI_PASSWORD` |
| 修改 IMU SPI 引脚 | `SPI_*_GPIO` 宏和接线 |
| 改变采样率/量程 | BMI160 配置宏和 `bmi160_init()` |
| 加入磁力计修正 Yaw | 在 `sensor_task()` 中读取磁力计并融合航向 |
| 修改姿态算法 | `sensor_task()` 内 `roll_acc`、`pitch_acc` 和各模式分支 |
| 新增舵机 | 在 `servo_init()` 新增 LEDC channel、状态变量和控制命令 |
| 新增网页控件 | `INDEX_HTML` 字符串内 HTML/CSS/JavaScript |
| 新增 HTTP 接口 | handler、`httpd_uri_t` 和 `config.max_uri_handlers` |

网页 HTML、CSS、JavaScript 当前内嵌在 `main.c` 的 `INDEX_HTML` 字符串中，便于单文件烧录，但不适合大型前端。功能扩大后建议把网页文件放入 SPIFFS 或 LittleFS 分区，使用静态文件服务，避免 C 字符串难以维护。

## 7. 常见故障排查

### 7.1 网页打不开

1. 查看串口中 `sta ip:` 后面的地址，不要假设 IP 永远是 `192.168.1.50`。
2. 确认 PC 和 ESP32 在同一路由器的同一网段。
3. 查看是否存在 `CHIP_ID=0xD1` 和 `Open http://...` 日志。
4. 若日志出现 `ESP_ERR_HTTPD_HANDLERS_FULL`，说明新增 URI 后没有增加 `config.max_uri_handlers`。

### 7.2 滑杆高频拖动后无法继续控制

当前版本通过独立 `/control` WebSocket 和 30 ms 命令限频避免 HTTP 请求堆积。若二次开发改回 HTTP 轮询，应实现“单请求在途 + 最新值覆盖”的发送队列，不能在每个 `input` 事件中直接并发 `fetch()`。

若设备日志出现重启、Wi-Fi 掉线、Brownout，优先排查舵机供电：外部 5V 是否足够、是否共地、是否有大电流导致 ESP32 电压下降。

### 7.3 Roll/Pitch 或旋转方向相反

先把板子静止放平，逐个使用网页的 `GX/GY/GZ 反向` 按钮测试。按钮改变轴符号后会自动零点复位。确认坐标方向正确后再调整 Three.js 模型的轴映射。

### 7.4 Yaw 漂移

这是没有磁力计时陀螺仪积分的正常现象。可选改善方案：静止时估计陀螺零偏、增加磁力计、用视觉定位或外部定位系统提供航向参考。单纯提高发送频率不能消除零偏漂移。
